\section{Metodología experimental}

\subsection{Plataformas}

El entorno local de desarrollo es WSL2 con Ubuntu 24.04 x86-64 sobre un AMD Ryzen 5 3600 de seis núcleos y doce threads, 7,7~GiB de memoria y 16~MiB de caché L3. Se utilizó GCC 13.3.0 y Open MPI 4.1.6. El proyecto se construye principalmente con CMake y mantiene un Makefile portable para el entorno académico.

La construcción de desarrollo habilita C11 y las advertencias \texttt{-Wall}, \texttt{-Wextra}, \texttt{-Wpedantic}, \texttt{-Wconversion} y \texttt{-Wshadow}. Como controles complementarios se emplean \texttt{clang-format}, \texttt{cppcheck}, AddressSanitizer, UndefinedBehaviorSanitizer y Valgrind. Los comandos efectivos se conservan en el archivo \texttt{README.md} del repositorio.

Según el material del curso, MPI se habilita en FING mediante el módulo \texttt{mpi/mpich-x86\_64}; los binarios se compilan con \texttt{mpicc} y se ejecutan mediante \texttt{mpirun} con una lista o archivo de hosts. Esta información se verificará en las máquinas antes de realizar mediciones.

\subsection{Configuraciones y procedimiento}

Se mantiene fijo el problema y se incrementan procesos MPI y threads OpenMP para evaluar escalabilidad fuerte. Cada configuración incluye una ejecución de calentamiento y cinco repeticiones; se reportan mediana, mínimo, máximo y desviación estándar poblacional. Los checkpoints se desactivan y se exige el mismo hash final en todas las muestras.

La validación usa tres tamaños: mínimo de $8\times6$ durante dos iteraciones, mediano de $256\times160$ durante diez y base de $1024\times640$. Todos emplean la misma semilla por comparación. La medición local preliminar usa una iteración base para limitar interferencias del entorno interactivo; en FING se aumentará la cantidad de iteraciones después de estimar el tiempo de reserva.

\subsection{Métricas}

Para $T_1$ secuencial y $T_p$ paralelo, se calculan
\begin{equation}
S_p=\frac{T_1}{T_p}, \qquad E_p=\frac{S_p}{p}.
\end{equation}
También se miden tiempos máximos por fase, desbalance $L=\max_i W_i/\overline{W}$, volumen lógico de comunicación y métricas funcionales del modelo. El trabajo $W_i$ es la cantidad de hogares elegibles cuya búsqueda de destino pertenece al proceso $i$.

\subsection{Reproducibilidad}

El script \texttt{scripts/ejecutar\_experimentos.py} crea un directorio por calentamiento y repetición, ejecuta las versiones secuencial e híbrida, valida hashes y produce \texttt{resumen.csv}. Fija \texttt{OMP\_PLACES=cores}, \texttt{OMP\_PROC\_BIND=close} y la cantidad de threads de cada configuración. Los resultados crudos no se versionan; el CSV consolidado utilizado por el informe se copia a \texttt{informe/datos} junto con el código y la configuración que permiten regenerarlo.
